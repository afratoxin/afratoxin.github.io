# 완성 문항 및 HWP 출력 검증

> 아래는 초기 출력의 검증 기록이며 원본 HWP 서식 일치에 대한 판단은 불충분했다. 정답 표·논평 상자·직접 문단 서식·글꼴을 복원한 현재 구현과 실제 비교 결과는 [원본 서식 보존 수정](2026-10-31-template-fidelity-correction.md)을 따른다.

## 요구와 구현

사용자는 JSON·제작 메모가 섞인 응답 대신 실제 HWP 양식에 맞춘 완성본을 우선 요청했고, 대안으로 바로 붙여 넣는 문항만 출력을 요청했다. 기본 프롬프트를 일반 텍스트의 완성 문항으로 바꾸고 해설 포함 및 기존 JSON을 선택 형식으로 유지했다. JSON을 가져온 작업에도 문항만 복사/TXT와 해설 포함 복사/TXT를 제공한다.

실제 로컬 양식은 A3 세로 한 페이지이며 왼쪽 문항·오른쪽 정답 및 해설 구조이다. 한글 2022 자동화로 원본 복사본을 읽어 표·스타일·페이지 설정을 유지한 HWP/HWPX를 만들었다. 소스 HWP와 임시 XML, 패키지, 생성 문항은 저장소에 포함하지 않는다. 원본 해시 불변을 확인했다.

## 확인 결과

- 전체 Node 279/279, Python 47/47 통과. HWP 부분 10개 검사는 페이지/스타일 보존, 좌우 본문 분리, 표·정오 표시, 기존 번호 보존, 글꼴 교체, 출력 충돌 보호, 지문·풀이·표·해설 누락 거부를 확인한다.
- 실제 로컬 브라우저에서 기존 작업 JSON 복원, 문항만 기본값, 세 출력 형식 전환, 프롬프트 무효화를 확인했다. 문항만에는 JSON 출력 지시가 없고 해설 모드에는 별도 해설 지시, JSON 모드에는 기존 스키마 지시가 있다.
- 문항만 복사를 누른 뒤 다른 입력칸에 실제 붙여 넣어 원문과 일치함을 확인했다. 브라우저의 TXT 다운로드도 열어 발문으로 시작하며 정답·AI 검토 항목이 없는지 확인했다.
- 지원금 예시는 의미를 유지하면서 규정을 간결하게 정리하고 다섯 기업의 사실관계를 표로 배치했다. 최종 금액은 만 원 단위 갑8200·을7700·병9500·정7700·무10000, 정의 가산 우선 가정은7600이다. ①~④ 참,⑤만 거짓이다.
- 원본 자체의 PDF에서도 HFT 글자가 누락되어 TTF 호환 글꼴을 적용했다. 오른쪽 정보 표의 마지막 열 잘림은 두 문단 배치로 해결했다. 이러한 조정은 원본을 보존한 완성본에만 적용한다.
- 최종 실제 HWP 다시 열기 및 좌우 전체 내용 대조, PDF 전체 내용 대조, A3 한 페이지, 원본 불변이 통과했다. PDF를 PNG로 렌더링하여 박스·표·선택지·오른쪽 해설에 잘림이나 겹침이 없는지 확인했다. 한글 덮어쓰기 확인창은 검증용 임시 출력 폴더에 새 파일로 저장한 뒤 복사하는 방식으로 피한다.
- 독립 코드 검토에서 본문 검증 범위가 발문·선택지에만 한정된 문제, 숫자 선택지 번호를 정규화한 후 원문과 잘못 비교하는 문제, 기존 발문 번호 중복을 발견했다. 최종 native XML의 좌우 본문을 기준으로 HWP/PDF의 전체 내용 검증을 수행하고 기존 번호를 보존하도록 수정했다. 해당 회귀 검사는 수정 전에 실패하고 수정 후 통과했다.

사이트의 HWP 생성은 브라우저 안에서 실행되지 않는다. 설치된 한글이 있는 이 환경에서 로컬 출력하며 문항 복사·TXT는 사이트에서 제공한다. 프롬프트는 출력 형식을 요청하는 지침이고 모든 후속 생성 결과의 내용·정답·한 페이지 적합성을 보장하는 것은 아니다.
