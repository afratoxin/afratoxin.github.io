# Author DB implementation plan

**Goal:** Deliver the user's approved writer-focused DB overhaul and publish a verified version.
**Architecture:** Independent search, analytic, authoring and research modules, integrated by app.js. Static local state with versioned validated imports.
**Tech stack:** Native browser ES modules, Node tests, Python/Pillow for source-bound metadata, GitHub Pages.
**Spec:** ../specs/2026-10-31-author-db-design.md

## Global constraints
The design spec constraints are binding. Preserve baseline answers, source assets, user state and current output features. No student features. No automatic external issue submission. New modules use version 20261031-author-db1.

## Review focus
1. Explicit exclusions must survive semantic scores and every sort.
2. Legacy saved author projects/reviews must survive migration and bad imports.
3. Diagram content must not count as zero workload or disappear in exports.
4. Exception treatment must not overwrite book answer or falsely mark all keys verified.
5. Mobile overflow, crop boundaries and print layouts must preserve source content.
