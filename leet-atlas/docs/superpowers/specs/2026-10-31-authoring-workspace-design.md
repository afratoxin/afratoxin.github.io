# 기출에서 새 문항으로 이어지는 제작 작업실

사용자가 설정한 목표와 무료·브라우저 처리 조건에 따라 진행한다. 사용자는 직접 생성이 어려우면 ChatGPT에 붙여 넣을 프롬프트를 제공하는 경로를 명시적으로 허용했다. 현재 E5는 검색 모델이며 생성 기능이 없다. 따라서 기존 검색을 재사용하고, 생성은 사용자가 ChatGPT 웹에서 실행하며, 결과를 사이트로 가져오는 접근을 선택한다. 유료 API는 기존 조건과 맞지 않고 브라우저 생성 모델 추가는 한국어 논증 정확도와 다운로드 부담이 검증되지 않았다. 별도 생성 모델 채택은 이번 접근에 필요하지 않다.

## 사용자 흐름

1. 문항 탐색과 상세의 ‘제작에 참고’ 링크로 기출을 가져오거나, 새 `author.html`의 제작 의도 입력으로 전체755문항을 검색한다. 링크는 해시를 써 입력 문장을 서버 URL 질의로 전달하지 않는다. 일반 검색·기출 분류·리더를 유지한다.
2. 참고 기출을 최대5개 선택한다. 각 기출의 분류 근거, 요약, 풀이 단계, 선택지 오류와 원문 확인 링크로 출제 논리를 소개한다. 관련성은 유사도이며 조건 충족 보장이 아니다. 사용자는 채택할 논리와 바꿀 소재를 자유롭게 적는다.
3. ‘제작 프롬프트 만들기’는 제작 의도, 사용자가 채택한 논리, 선택한 기출의 원문·모든 선택지·해설·함정·분류 근거, 분류 어휘와 응답 형식을 함께 넣는다. 자료를 조용히 잘라내지 않는다. 기출은 참고 자료로 인용하고 새로운 소재·수치·논증 구성을 요구한다. 출력은 완전한 지문·발문·5개 선택지·정답·단계별 풀이·선택지별 판정·분류 근거·검토 기록을 담는 JSON 하나다. 복사와 파일 다운로드를 제공하고 사용자가 ChatGPT를 열 수 있다.
4. 사용자가 응답 JSON을 붙여 넣으면 문항과 해설, 분류 근거, AI가 보고한 검토 결과를 동시에 표시한다. 형식 오류·모르는 분류·정답 표시 불일치·빈 해설 등을 검증하고 잘못된 입력은 이전 초안을 지우지 않는다. 코드 실행이나 HTML 해석 없이 텍스트로 표시한다. 직접 수정은 응답 편집 후 다시 반영한다.
5. AI가 보고한 통과를 독립적인 정답 검증으로 취급하지 않는다. 형식 검사와 AI 검토를 구분하고 정답 유일성·조건 완결성·전 선택지 판정·기출 차별성·분류 근거의 수동 확인을 기록한다. 수정 시 기존 수동 확인은 초기화한다. 수정·재검토 프롬프트에는 현재 초안과 검토 기록을 포함한다.
6. 현재 작업은 이 브라우저에 저장하고 JSON으로 내보내고 복원한다. 저장 실패는 사용자에게 알리고 화면 작업과 다운로드는 유지한다. 파일 복원도 검증 후 원자적으로 반영한다. JSON과 읽을 수 있는 Markdown 문항을 내려받을 수 있다.

실제 생성 시험에서 문법 오류와 ‘해설에서만 수정하고 선택지는 그대로 남기는’ 불일치가 확인되어, 받은 응답과 검사 오류를 포함하는 보완·독립 재검토 프롬프트를 추가한다. 풀이·단계의 확정 결과를 먼저 작성하고 실제 선택지를 그 결과에 맞추어 출력하도록 요청한다. 이는 오류를 줄이는 지침이며 사이트의 자동 논리 증명으로 표시하지 않는다. 수정할 응답이 바뀌면 이전 보완 프롬프트도 무효화한다. 새 작업은 현재 작업을 JSON으로 백업한 뒤 시작한다.

## 구조와 판정 범위

`authoring.mjs`: 자료·프롬프트·입출력 검증·직렬화의 순수 함수. `authoring-ui.mjs`: DOM과 검색 상태·저장·다운로드. `authoring.css`: 기존 디자인 변수를 따르는 반응형 화면. `author.html`: 독립 진입점과 기존 메뉴. 기존 app.js는 참고 링크만 추가한다. archive.json은 변경하지 않는다. 개인 교정본을 외부 프롬프트로 암묵적으로 내보내지 않고 공개 원문을 사용한다.

응답 schemaVersion=1, title, passage, question, choices(5문자열), answer(1..5), solution, steps, optionAnalyses(각 number/isAnswer/reason), classifications(각 axis/label/reason), review(각 criterion/status/evidence)를 받는다. 검토 기준은 answerUniqueness, sufficiency, optionValidity, originality, classification. classifications의 axis는 domain/field/subject/type/logic이며 subject를 제외한 label은 기존 분류에 있어야 한다. 검토 상태는 pass/revise/uncertain이다. 하나라도 revise/uncertain이 있으면 검토 보류로 보여 준다. 모두 pass여도 AI 자체 검토로만 표시한다. 서버 AI나 자동 논리 증명은 제공하지 않는다.

## 완료 증거

일반 제작 요청→실제 검색→기출 선택→전체 자료가 포함된 프롬프트→완성 응답 가져오기→분류·검토 표시→내보내기와 복원의 브라우저 흐름을 확인한다. 형식검사·안전한 렌더링·잘못된 입력 후 보존·저장 실패·검색 경합을 검증한다. 기존 전체 테스트와 공개 배포를 확인한다. 최종 목표의 완료는 이 모든 경로가 실제 공개 사이트에서 확인되어야 한다.
