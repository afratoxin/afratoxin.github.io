# 문항 탐색: 입력 방식 구분과 출제 특징 검색

상태: 검토용 설계. 공개 사이트의 동작은 아직 변경하지 않았다.

## 사용자 정정: 예시를 넘어서는 일반 자연어 검색

사용자는 네 가지 검색어가 요구의 전부가 아니며, 처음 입력하는 임의의 문장도 전체 문항과 즉시 연관성을 비교해야 한다고 명확히 했다. 아래 예시·특성은 검색을 제한하는 지원 목록이 아니다. 이 절이 뒤의 필수 조건 자동 적용·예시 중심 완료 기준보다 우선한다.

- 검색어 사전이나 질문별 조건 분기로 처리하지 않는다. 처음 보는 자연어도 같은 검색 경로에서 의미를 계산해 전체 755문항과 비교한다. 문항 번호 정확 검색은 편의 기능으로 유지한다.
- 검색어를 미리 등록하는 대신, 각 문항의 원문·다섯 선택지·모든 해설·보기 판단·놓치기 쉬운 지점·근거 있는 출제 특징을 검색 자료로 준비한다. 선택지별 역할과 오류 설명도 독립 문단으로 넣는다. 문항별 자유로운 서술 자료이므로 고정 태그 밖의 특징도 검색 대상이다.
- 넓은 후보를 찾는 의미 검색과 표현 검색을 결합하고, 상위 후보의 근거 문단을 입력 문장과 함께 비교해 관련성을 다시 평가하는 일반적인 두 단계 검색을 검토한다. 재평가 모델은 한국어 정확도·브라우저 실행 시간·추가 다운로드를 실측한 뒤 채택 여부를 정하며, 검증 전 특정 속도나 기존 118MB만으로 충분하다고 단정하지 않는다.
- 입력 문장에 알려진 분류어가 없다는 이유로 후보를 차단하지 않는다. 태그와 구조 프로필은 순위와 근거를 보강한다. 자연어를 고정된 필수 필터 집합으로 강제 변환하지 않는다. 사용자가 직접 고른 필터만 반드시 적용하고, 읽어 낸 조건은 수정 가능한 보조 정보로 보여 준다.
- 결과에는 질문과 관련된 실제 원문·선택지·해설 문단을 붙인다. 범용 생성 모델 없이 새로 추론한 판정 이유를 생성하지 않으며, 근거가 약하면 약하다고 표시한다. 관련성 비교와 모든 논증을 정확하게 해결하는 능력은 구별한다.
- 브라우저에서 처리하고 외부 유료 추론 API를 쓰지 않는 조건을 유지한다. ‘즉시’는 자료 준비 후 빠르게 1차 후보를 보이는 목표이며, 추가 정밀 비교는 완료 상태를 명확히 표시한다. 첫 모델 다운로드와 느린 기기의 실제 시간을 숨기지 않는다.
- 주어진 네 문장은 회귀 평가용 일부 사례다. 문항 특징·관계·형식·풀이 방식을 다양하게 조합한 미리 보지 않은 문장과 바꿔 쓰기를 따로 평가한다. 질문/ID별 정답 목록을 검색 응답에 넣어 예시만 맞추지 않는다.

화면 시안의 네 예시는 입력 방식을 설명하는 버튼일 뿐이다. 현재 시안의 고정 예시 전환은 실제 검색 엔진 구현이 아니며, 구현에서는 입력한 모든 자유 문장이 일반 검색 경로를 이용해야 한다.

## 목적과 확정된 요청

사용자는 새로운 문항을 만들 때 참고할 기출을 자연어로 찾고 싶다. 현재의 검색 방식 선택과 검색 입력칸이 혼동되지 않도록 화면을 개선하고, 소재뿐 아니라 풀이 과정·선택지 형식·빈칸·선택지의 논증 오류까지 검색해야 한다.

사용자가 제시한 예시:

1. 강화약화 문항인데 A와 B 모두가 동의하는 근거로 잘못 약화나 강화를 친 경우.
2. 법률 문항인데 계산이 어느 정도 들어감.
3. 단일 정답 문항. 사용자 확인: ㄱ·ㄴ·ㄷ 합답형이 아닌 독립 선택지형을 뜻함.
4. 문항에 빈칸 박스가 존재해서 그것을 채우는 느낌.

별도 계정·유료 추론 API 없이 기존 GitHub Pages와 브라우저 의미 검색을 유지한다. 모델의 첫 다운로드 약 118MB와 실행 자료 안내도 유지한다. 원문·정답·기존 해설을 검색 개선 때문에 바꾸지 않는다.

## 현재 동작과 확인된 한계

현재는 같은 검색 입력칸 옆의 작은 선택 메뉴로 참고 문항 추천/키워드 검색을 바꾼다. 모바일에서는 선택 메뉴가 입력칸 아래로 내려가 입력의 목적이 먼저 드러나지 않는다. 검수 상태도 같은 줄에 있어 검색 방식과 관리 필터의 위계가 섞인다.

`reference-search.mjs`의 문서와 가벼운 검색 특징은 제목·분류·원문·요약·풀이 단계 중심이다. `statements`, 다섯 선택지의 해설, `pitfalls`는 검색 문서에 포함되지 않아 상세한 오류 구조를 놓친다. 최종 정답 선택지 해설만 보여 주는 현재 상세 화면과 별개로, 데이터에는 다섯 선택지 해설이 남아 있다.

현행 모델과 점수 결합을 실제로 실행한 결과:

- 첫 예시에서 2012년 25번은 누락되고 2013년 2번은 17위였다.
- 법률+계산은 1802·2703·1807 등을 상위에서 찾지만 두 조건을 모두 충족한다고 보장하지 않는다. 가벼운 분류 검색의 `법` 부분 문자열은 운동법칙까지 법률로 잘못 처리한다.
- 단일 정답은 문항 형식 대신 단일 조상·단일 가격 등의 소재로 매칭된다.
- 빈칸 박스 예시는 의미 검색을 포함해도 결과가 없었다.

유사도 점수를 조정하는 것만으로 해결할 수 없는 정보 부족이다.

## 접근 방식

### 제안: 기존 의미 검색 + 근거가 있는 문항 특징

의미 검색은 자유로운 표현으로 후보를 찾고, 별도로 기록한 문항 형식·필요한 풀이·선택지별 오류 구조를 결합해 조건 충족과 순위를 판단한다. 이미 사용자가 고른 무료 브라우저 방식의 확장이다. 새로운 서비스·모델 선택은 필요하지 않다.

모델 유사도와 동의어만 확대하는 방법은 구현량이 작지만 숫자 등장/계산 필요, 박스 있음/빈칸 완성을 구별할 근거가 부족하다. 사용자가 직접 상세 태그를 먼저 선택하는 방법은 명확하나 출제 용어를 모르더라도 자연어로 찾아야 한다는 목적에 맞지 않는다. 따라서 자연어로 시작하고 시스템이 읽어 낸 조건을 확인·해제할 수 있는 방식을 제안한다.

외부 AI 호출은 앞서 정한 비용·계정·브라우저 처리 조건 때문에 이번 범위에 넣지 않는다.

## 화면

검색 방식은 선택 메뉴 대신 나란히 보이는 두 개의 선택 버튼으로 둔다. 좁은 화면에서도 두 버튼의 이름과 짧은 설명을 함께 볼 수 있게 한다.

| 방식 | 버튼 아래 설명 | 입력칸의 보이는 이름 | 입력과 실행 |
| --- | --- | --- | --- |
| 설명으로 추천받기 | 만들고 싶은 문항의 특징과 비슷한 기출 찾기 | 찾고 싶은 문항의 특징 | 여러 줄 입력, ‘참고 문항 찾기’ |
| 단어로 검색하기 | 입력한 단어가 실제로 포함된 기출 찾기 | 검색할 단어 또는 문항번호 | 한 줄 입력, ‘단어로 검색’ |

추천 입력 안내는 소재·풀이 방식·선택지 형식·논증의 함정을 문장으로 적도록 안내한다. 네 가지 사용자 예시를 누르면 추천 방식으로 전환하고 해당 문장을 입력한다. 예시마다 별도 결과 목록을 하드코딩하지 않는다.

키워드 입력 안내는 공백으로 나눈 모든 단어가 검색 대상 텍스트에 포함되는 방식임을 분명히 한다. 두 방식의 입력을 따로 기억하며, 방식을 전환해도 다른 방식의 문장이 입력된 채 실행되지 않게 한다.

실행 버튼은 현재 입력으로 결과를 확정한다. 추천 입력은 입력 도중 기존 결과를 새 입력의 결과처럼 표시하지 않는다. 입력 변경 시 ‘조건을 수정했습니다. 참고 문항 찾기를 눌러주세요’ 상태를 보여 주고, 실행하면 기존 취소·요청 순서 보호를 이용한다. 키워드는 기존 빠른 입력 검색을 유지해도 되며 버튼과 Enter도 같은 결과를 실행한다. 긴 추천 문장은 Enter로 줄을 바꿀 수 있고 Ctrl/Cmd+Enter로 실행할 수 있다.

검수 상태는 검색 입력 영역에서 분리해 북마크·목록 필터 쪽에 ‘검수 상태’라는 이름으로 놓는다. 기존 분야·연도·북마크 필터는 유지한다. 정렬과 페이지 나눔도 유지한다.

추천 결과 위에는 ‘검색에 반영한 조건’을 표시한다. 예: `법률` `계산 필요`, 또는 `독립 선택지형`. 직접 표현되고 확실히 인식한 분야·선택지 형식·계산 필요·빈칸 완성·박스 빈칸·검수된 논증 오류 조건은 모두 필수 조건으로 적용하고 각 조건을 해제할 수 있게 한다. ‘확인된 일치’에는 인식한 필수 조건 전체의 확인 근거가 있어야 한다. 부정 표현은 제외 조건으로 표시한다. 해석하지 못한 부분은 임의로 조건을 추가하지 않고 의미 유사도에만 반영한다.

검수된 조건을 충족하는 결과와 추가 검토가 필요한 유사 후보는 명시적으로 구별한다. 확인된 결과가 없더라도 필수 조건을 몰래 완화하지 않는다. ‘확인된 일치 없음’과 함께 조건 해제/유사 후보 보기로 이어질 수 있다. 유사 후보에도 어떤 조건이 미확인인지 적는다. 유사도는 정답 확률이나 일치율 %로 표시하지 않는다.

## 검색용 문항 특징

755문항 전체에 검색 전용 프로필을 만든다. 원본을 덮어쓰지 않고 공개 원문의 버전과 연결된 별도 자료로 관리한다. 분류를 못 했다는 이유로 부정값을 넣지 않고 `unknown`을 구별한다.

최초 배포 범위는 전체 755문항을 한 번씩 점검한 기본 특성 프로필과, 강화·약화로 분류된 전체 문항 및 해설에서 관련 오류 표현이 발견되는 후보의 논증 관계 검수다. 빈칸·선택지 형식·계산의 자동 후보와 분류 예외를 모두 확인하고, 박스 모양·이미지 선택지·모호한 논증 관계는 원문 이미지/해설을 대조한다. 그래도 판정 근거가 부족한 개별 특성은 이유와 함께 `unknown`으로 남길 수 있다. 네 예시의 정답 목록만 넣고 전체 검수를 생략하는 것은 완료로 인정하지 않는다. 다만 모든 가능한 오류 유형을 전 문항에서 완전히 분류했다고 주장하지 않는다. 특성별 확인/미확인 수와 검수 범위는 결과 안내 또는 도움말에서 확인할 수 있게 한다. 이는 구현자가 제안하는 첫 배포 범위이며 사용자 검토 대상이다.

### 분야와 계산

- 법률은 기존 대범주 `법률`의 정확한 소속으로 판정한다. ‘법’이라는 글자나 운동법칙 같은 이름으로 추론하지 않는다.
- 계산 필요는 기존 `수식 계산` 분류와 실제 연산이 필요한 원문·해설을 근거로 한다. 숫자·날짜·비율이 한 번 나온다는 이유로 계산 문항으로 분류하지 않는다.
- 계산의 종류는 금액·비율·수량·기간·확률 등 실제로 확인되는 수준으로 기록한다. 계산량이나 난도를 근거 없이 수치화하지 않는다.
- 법률 소재에서 과학 계산을 하는 사례와 법률 규칙을 적용해 금액 등을 산출하는 사례는 구별해 설명할 수 있게 한다. 법률+계산의 기본 요청에서는 둘 다 후보가 될 수 있지만 적용 법규 산정이 확인된 경우 근거를 표시한다.

현재 자료에는 법률 224문항, 그중 기존 수식 계산 분류가 있는 문항 31개가 있다. 이것은 시작 자료이며 새 특성 검수 후의 최종 개수를 미리 확정하지 않는다.

### 선택지 형식

서로 독립된 진술, 단일 수치·값, 보기 집합 조합, 순서 배열, 짝·대응 선택, 도형·이미지, 미확인 등을 구별한다. ㄱ·ㄴ·ㄷ 이외에도 `(가)와 (다)`, ㉠·㉡, 갑·을의 조합이 있어 이를 검사한다. 조합 표시가 없다는 이유만으로 독립 진술형으로 판정하지 않는다.

‘단일 정답’, ‘합답형 말고’, ‘ㄱㄴㄷ 조합 아닌 것’, ‘①~⑤가 각각 문장인 것’은 독립 선택지형 조건으로 연결한다. 단일 수치형까지 포함할지는 별도의 조건으로 남겨 현재 사용자가 확인한 독립 진술 범위를 유지한다.

여덟 문항 p014·2020·2236·2319·2425·2521·2623·2723은 선택지 텍스트가 모두 비어 있다. 이들은 이미지 확인 전까지 미확인/이미지 의존으로 둔다. 한글 자모는 NFKC 전후로 달라지므로 원문 형식 판정과 검색어 정규화를 일관되게 다룬다.

### 빈칸과 박스

`빈칸 완성 과제`와 `사각형 박스로 표현된 빈칸`을 별도 특성으로 둔다. 본문·대화·수식·표의 빈칸도 구별한다. 원문 문장 ‘빈칸’은 과제를 확인하는 근거가 될 수 있지만 충분조건은 아니다. 지문 전체가 박스로 둘러싸였거나 소재로 빈칸을 설명하는 문항을 제외한다.

박스의 시각적 모양은 기존 원문 이미지에서 검수한 경우에만 확인됐다고 표시한다. 텍스트 추출로 모양을 복원했다고 주장하지 않는다. 빈칸형과 독립 선택지형은 독립 조건이므로 빈칸+합답형도 허용한다.

### 논증 관계와 선택지의 오류

문항 단위의 광범위 태그만 붙이지 않고, 해당 보기/선택지 단위로 구조를 기록한다.

- 어떤 입장·가설·화자를 비교하는지.
- 공통 전제/관찰/예측과 서로 다른 주장.
- 제시된 근거가 각각의 입장에 미치는 영향: 강화·약화·양립·미확인 등.
- 선택지가 주장한 영향과 그 주장이 타당하지 않은 이유.
- 양쪽과 양립하지만 상대적 판별력이 없는 경우, 양쪽을 함께 강화/약화하는 경우, 한쪽이 이미 인정한 전제를 반박으로 삼는 경우를 구별.

‘양측 공통 → 무관’이라는 규칙은 사용하지 않는다. 예를 들어 1302 ㄱ은 특검의 통제 부재가 양측을 실제로 약화하는 대조 사례다. 1302 ㄷ은 특검 필요성의 공통 인정으로 A가 약화된다고 오판하는 경우다.

기존 `options.correct`는 문제의 정답 선택 여부이므로, 선택지 진술 자체의 타당성이나 강화·약화 방향과 혼동하지 않는다. 옳지 않은 것을 고르는 문제에서는 틀린 진술이 정답이 될 수 있다.

## 근거와 갱신

각 특성에는 `confirmed / inferred / unknown` 상태, 원문 또는 해설의 위치, 실제 짧은 근거문, 자료 해시를 둔다. 형식은 원문/선택지로, 논증의 미묘한 관계는 원문과 선택지·보기 해설을 대조해 검수한다. 자동 추출은 후보를 만들 수 있지만 확인된 관계로 즉시 승격하지 않는다.

본문·원본 선택지·모든 선택지 해설·보기 판단·놓치기 쉬운 지점·검수된 검색 프로필을 검색 문서에 포함한다. 구조별 짧은 문서를 따로 두어 긴 지문에 해설 핵심이 묻히지 않게 한다. 기존 고정 모델로 자료만 다시 계산하며 모델 파일을 추가로 늘리지 않는다.

의미 검색은 후보와 순위를 돕고, 확인된 필수 조건은 별도로 검사한다. 원문/분석이 수정되어 근거 해시가 맞지 않으면 해당 확인 상태를 무효화하고 재검수 대상으로 표시한다. 개인 교정본의 표현 검색은 유지하고 사전 의미 자료가 공개 원문 기준임을 계속 안내한다.

결과 근거는 한 가지를 구체적으로 보여 준다. 예: ‘①·②: 두 가설과 양립하는 관찰을 A 강화/B 약화로 평가’ 또는 ‘법률 · 보상금의 비율 계산’ 또는 ‘대화 끝 [A]의 박스 빈칸’. 검수되지 않은 추측을 이처럼 단정하지 않는다. 원문과 관련 선택지/해설의 실제 내용을 열어 확인할 수 있게 한다. 상세 화면에서 정답 해설만 보이더라도 검색 근거로 사용한 다른 선택지의 해설을 확인할 수 있는 연결을 제공한다.

## 구현 순서와 완료 기준

1. 두 방식의 버튼·입력 이름·안내·실행·분리된 입력 상태와 필터 배치를 구현한다.
2. 전체 문항의 형식·계산·빈칸 후보를 추출하고 애매한 형식과 이미지 의존 사례를 검수한다. 확인 근거와 unknown을 보존한다.
3. 모든 해설을 검색에 포함하고 강화·약화 문항의 공통 근거/차별적 증거 오류를 검수한 프로필을 만든다. 유사한 표현과 부정 조건도 평가한다.
4. 확인된 조건 검사와 의미 순위를 결합하고, 확정 일치/유사 후보를 분리한다. 네 예시뿐 아니라 보지 않은 바꿔 쓰기와 잘못 맞을 만한 대조 문항을 평가한다.
5. 검색 문서를 다시 계산하고 기존 기능 검사·실제 브라우저 의미 검색·배포 후 화면을 확인한다.

완료 기준:

- 사용자는 작은 메뉴를 열지 않고 두 방식의 차이와 지금 입력할 내용을 알 수 있다. 모바일·키보드·스크린리더에서도 방식과 입력 이름이 연결된다.
- 사용자의 첫 구상 상위 결과에 1225와 1302가 실제 선택지 근거와 함께 나타나고, 1302 ㄱ을 같은 오류 사례로 분류하지 않는다.
- 법률+계산의 확인 결과에 법률 외 분야나 숫자만 등장하는 문항이 섞이지 않는다.
- 독립 선택지형을 단일 조상·단일 가격 소재로 검색하지 않으며 합답형·순서형·미확인 형식을 섞지 않는다.
- 박스 빈칸은 확인된 원문 과제로 찾고 일반 지문 박스를 같은 형식으로 처리하지 않는다.
- 분류 미확인·준비 실패·개인 교정본·원문 변경 시의 한계를 숨기지 않는다. 모델 준비 실패 시에도 확인된 조건과 단어 검색을 사용할 수 있다.
- 기존 문항 원문/이미지/정답/해설, 755문항 전체 범위, 북마크, 필터, 정렬, 상세 이동을 보존한다.

세부 점수 가중치, 파일 분할, 후보 추출 정규식, 모바일 줄바꿈과 여백은 구현자가 검증하며 정한다. 새 출제 원고 생성, 자동 정답 판정, 연산 난도 자동 등급화는 이번 범위가 아니다.
