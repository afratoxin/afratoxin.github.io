# 강의록 단독 풀이 가능성 전수 감사

사용자 보완 요구: 족보 문항이라도 제공한 강의록 근거만으로 풀 수 없으면 배제한다. 강의당 최소20문항, 자연스러운 5지선다와 교수별 족보 스타일이라는 원래 요구를 유지한다.

- [x] 기존225문항을 세 묶음으로 나누어 원저자와 다른 검토자가 감사한다. 정답판별에 필요한 사실이 강의 슬라이드·수업주석에 명시되어 있는지 실제쪽수별 확인. 강의 파일 말미 재수록 족보와 외부지식은 근거에서 제외한다.
- [x] 근거없는 기존문항은 제거하고 강의내용만으로 새문항을 작성한다. 줄기·선지·정답 변경시 새ID를 사용해 기존풀이기록 혼입을 방지한다. 해설도 강의범위 안으로 한정한다.
- [x] 모든최종문항에 `lectureBasis.summary/pages`로 결정적근거를 기록한다. 기존225개모두의 유지·수정·교체·제외 판단을 검토기록으로 남긴다.
- [x] 해설화면에 강의록 결정적근거를 표시하고 족보는 유형참고로 분리한다. 페이지근거·감사범위·문항수·새ID 및기록호환성 확인.
- [ ] 기존주소에 수정본을게시하고 실제반영확인.

검사 시작: 현재은행은 강의쪽수 연결은 있으나 정답판별 근거를 전수 증명하는 데이터가 없으므로 강화된 검증에서 실패해야 한다. 기계검사는 근거기록의 빠짐을 검출하며 실제내용의 충분성은 PDF대조감사로 판단한다.

검증 결과: 최초 은행에서 명시근거 누락 실패를 확인한 뒤,225문항의 근거·269개현재인용페이지·225개감사기록 연결이 모두 통과했다. 교체45·선지/해설/근거수정78·유지102이며, stem/choices/answer가바뀐52개는 새ID이다. 핵심동작 테스트11개통과,독립코드검토중요오류없음,실제브라우저에서교체문항미풀이·구세션무효화·채점후강의록판단근거·원본쪽연결을확인했다. 게시결과는이커밋에대응하는GitHubPages배포와실제주소의버전으로확인한다.
